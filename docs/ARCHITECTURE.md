# Hooman Finance — سند معماری (پیش‌نویس ۱)

## ۱. تصمیم‌های فنی پیشنهادی

| موضوع | پیشنهاد | دلیل |
|---|---|---|
| زبان | TypeScript | هسته محاسباتی را می‌توان بدون گوشی، با تست خودکار اجرا و بررسی کرد |
| رابط موبایل | React Native (Expo) | خروجی APK اندروید، پشتیبانی RTL، توسعه سریع |
| پایگاه داده | SQLite محلی (expo-sqlite) | پایدار، آفلاین، مناسب داده مالی |
| رمز ورود | ذخیره هش با salt در Secure Store (Keystore اندروید) | رمز هرگز به‌صورت متن خام ذخیره نمی‌شود |
| تقویم | شمسی (jalaali-js)؛ ذخیره داخلی میلادی ISO | محاسبات ساده، نمایش شمسی |
| اعداد | عدد صحیح مقیاس‌دار / decimal.js، نه float | جلوگیری از خطای اعشاری |
| قیمت روز | رابط `PriceProvider` قابل تعویض + ورود دستی | عدم وابستگی به یک سایت |

> جایگزین: Flutter (پیشنهاد خود پروژه). مزیت Expo در اینجا این است که منطق مالی را می‌توانم اینجا اجرا و تست کنم.

## ۲. لایه‌های برنامه

1. **core/** (منطق مالی خالص، بدون UI، با تست کامل): میانگین موزون، سود/زیان، موجودی، اقساط، دارایی خالص
2. **db/**: schema، migration، repository
3. **services/**: قیمت‌ها، پشتیبان‌گیری، امنیت، خروجی
4. **ui/**: صفحات، تم روشن/تاریک، اندازه فونت

اصل مهم: **هیچ موجودی یا سودی ذخیره نمی‌شود؛ همه‌چیز از روی دفتر تراکنش‌ها بازمحاسبه می‌شود.** به همین دلیل ویرایش یا حذف تراکنش قدیمی همیشه نتیجه درست می‌دهد.

## ۳. صفحات

- **خانه**: دارایی خالص، ارزش کل دارایی‌ها، نقد، مطالبات، بدهی‌ها، سود/زیان، فهرست دارایی‌ها
- **دارایی‌ها**: فهرست، افزودن دارایی، جزئیات (موجودی، میانگین خرید، ارزش روز، سود/زیان، تاریخچه)
- **معاملات**: همه تراکنش‌ها، جست‌وجو، فیلتر، ثبت/ویرایش/حذف
- **اشخاص و حساب‌ها**: فهرست اشخاص، طلب/بدهی، اقساط، پرداخت‌ها، تسویه
- **تنظیمات**: واحد (تومان/ریال)، تم، اندازه فونت، قفل، پشتیبان، بازیابی، خروجی

جریان ثبت معامله: انتخاب دارایی ← خرید/فروش ← فرم ← **صفحه تأیید** ← ثبت.


- مبالغ به **ریال (عدد صحیح)** ذخیره می‌شوند؛ تومان فقط در نمایش است.
- حذف نرم (`deleted_at`) برای جلوگیری از حذف تصادفی؛ بازیابی ممکن است.

## ۵. فرمول‌ها

بازپخش تراکنش‌ها به ترتیب تاریخ، برای هر دارایی:

- **خرید**: `هزینه_جدید = هزینه_قبلی + مقدار×قیمت + کارمزد`؛ `موجودی += مقدار`؛ `میانگین = هزینه ÷ موجودی`
- **فروش**: فروش بیش از موجودی رد می‌شود. `سود تحقق‌یافته = (مقدار×قیمت − کارمزد) − مقدار×میانگین`؛ میانگین تغییر نمی‌کند؛ `هزینه −= مقدار×میانگین`
- **سود تحقق‌نیافته** = `موجودی×قیمت روز − بهای تمام‌شده موجودی`
- **دارایی خالص** = ارزش دارایی‌ها + نقد + مانده مطالبات − مانده بدهی‌ها
- پس از هر ویرایش/حذف، کل تاریخچه دوباره بازپخش می‌شود؛ اگر در هر لحظه موجودی منفی شود، ویرایش رد می‌شود.
- مانده طلب/بدهی = `اصل − مجموع پرداخت‌ها`؛ قسط سررسیدشده = سررسید گذشته و پرداخت‌نشده

## ۶. ابهام‌هایی که باید روشن شوند

1. خرید طلا/دلار از نقد کسر شود یا نقد جدا مدیریت شود؟
2. وام دادن/گرفتن روی موجودی نقد اثر بگذارد؟
3. قیمت روز طلا: گرم ۱۸ عیار، مثقال، یا سکه؟ دلار: بازار آزاد؟
4. منبع قیمت خودکار: TGJU API رسمی عمومی ندارد؛ چه جایگزینی قابل قبول است؟
5. کارمزد فروش از مبلغ فروش کم شود (پیش‌فرض این سند)؟

## ۷. مراحل

- **مرحله ۱**: هسته محاسباتی + تست، صفحات خانه/دارایی/معاملات، ذخیره SQLite
- **مرحله ۲**: اشخاص، اقساط، پرداخت‌ها، تست کامل
- **مرحله ۳**: قیمت روز، تم و فونت، قفل، پشتیبان، گزارش
- **مرحله ۴**: تست روی گوشی، رفع خطا، APK

## تصمیم: نقد و دارایی‌ها حساب‌های مستقل‌اند (جایگزین «کسر خودکار از نقد»)

- موجودی نقد = واریزها − برداشت‌ها. فقط همین. خرید/فروش/دریافت دارایی هرگز نقد را تغییر نمی‌دهد.
- ارزش کل = نقد + Σ (مقدار هر دارایی × قیمت روز). خرید دوباره فقط مقدار همان دارایی را زیاد می‌کند.
- حقوق یا هدیه‌ی نقدی = «واریز». هدیه‌ی دارایی = نوع جدید «receive» (مقدار زیاد می‌شود، پایه‌ی هزینه = ارزش روز دریافت، بدون کارمزد، جزو «مجموع خرید» نیست).
- دلیل: درآمد (حقوق، هدیه) از بیرون وارد می‌شود و کاربر خودش تصمیم می‌گیرد چه مقدار نقد بماند و چه مقدار طلا شود؛ بدون اتصال، حساب هرگز «بدهکار» نمی‌شود.

## اشخاص، وام و اقساط (src/core/people.ts)

- شخص (Person) ← وام/قرض (Debt: lent یا borrowed، مبلغ کل بازپرداخت، تاریخ، برنامه‌ی اقساط اختیاری) ← پرداخت‌ها (DebtPayment).
- مانده = مبلغ کل − جمع پرداخت‌ها؛ هیچ مانده‌ای ذخیره نمی‌شود. پرداخت‌ها به ترتیب روی اقساط می‌نشینند (پرداخت‌شده/نیمه‌پرداخت/در انتظار/سررسید گذشته).
- سرمایه‌ی خالص = نقد + ارزش دارایی‌ها + طلب‌ها − بدهی‌ها.
- اتصال به نقد فقط با گزینه‌ی «fromCash» روی وام یا پرداخت (پیش‌فرض خاموش). اثر نقدی: گرفتن وام +، دادن وام −، پرداخت من −، دریافت از او +.
- اعتبارسنجی: پرداخت بیشتر از مانده، پرداخت قبل از تاریخ وام و جمع اقساط بیش از مبلغ وام رد می‌شود.

## نسخه‌ی اندروید (اولیه)

- App.tsx (Expo) همان صفحه‌ی web/dist را داخل WebView اجرا می‌کند (src/native/appHtml.ts با `npm run web:build` ساخته می‌شود).
- داده‌ها در localStorage وب‌ویو می‌ماند. دریافت قیمت از TGJU از طریق fetch بومی و پل پیام (window.__bridgeReply) انجام می‌شود و فقط به آدرس https://call.tgju.org/ اجازه دارد.
- دکمه‌ی برگشت اندروید با window.__hwBack مدیریت می‌شود.
- ساخت APK: `.github/workflows/build-apk.yml` (GitHub Actions) یا محلی با `npm install && npm run apk`.
- مرحله‌ی بعد: انتقال رابط به React Native بومی، SQLite، قفل برنامه، پشتیبان‌گیری و فونت آفلاین.

## سهام بورس ایران (src/core/tsetmc.ts)

- قیمت آخرین معامله از سرویس عمومی TSETMC (cdn.tsetmc.com/api). جست‌وجوی نماد: `Instrument/GetInstrumentSearch/{نام}`، قیمت: `ClosingPrice/GetClosingPriceInfo/{InsCode}`.
- کد نماد (InsCode) در `asset.priceKeys.tsetmc` ذخیره می‌شود. قیمت فقط وقتی اعمال می‌شود که عدد صحیح مثبت، تاریخ‌دار و حداکثر ۴ روز قدیمی باشد؛ جهش بیش از ۳۰٪ هم رد می‌شود.
- فرمت پاسخ از کتابخانه‌های متن‌باز گرفته شده و با پاسخ زنده تأیید نشده است؛ فرم دارایی «قیمت آزمایشی» نشان می‌دهد تا کاربر با سایت مقایسه کند. فقط اپ اندروید به این آدرس‌ها دسترسی دارد (App.tsx: ALLOWED_FETCH).
- درخواست‌ها فقط با زدن «به‌روزرسانی قیمت‌ها» (و بررسی دوره‌ای) و فقط برای نمادهای کاربر ارسال می‌شود.

## نمودار سهم دارایی‌ها و آیکون‌ها

- خانه: نوار افقی برای سهم هر بخش (نقد، هر دارایی، طلب‌ها) با درصد؛ بدهی‌ها جدا نوشته می‌شود. رنگ‌ها از پالت دسته‌ای ۸ رنگ و بر اساس هویت دارایی ثابت است.
- آیکون‌ها (web/icons.ts) همه SVG داخلی‌اند: پرچم‌ها، سکه‌ی طلا/نقره، سکه‌ی دلاری برای تتر (لوگوی رسمی شرکت‌ها استفاده نمی‌شود).

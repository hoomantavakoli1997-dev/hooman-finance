# مهاجرت امن ذخیره‌سازی دارا به SQLite

## وضعیت این مرحله

این تغییر فقط زیرساخت ذخیره‌سازی SQLite را اضافه می‌کند. هنوز مسیر ذخیره‌سازی برنامه از `localStorage` به SQLite تغییر نکرده است و فایل قدیمی پاک یا بازنویسی نمی‌شود.

## تصمیم فعلی

برای کاهش ریسک مهاجرت، در گام اول کل وضعیت معتبر برنامه به‌صورت یک JSON snapshot در یک ردیف SQLite ذخیره می‌شود. این روش:

- ساختار فعلی Store و داده‌های مالی را بدون تبدیل ناقص حفظ می‌کند.
- جایگزینی snapshot را با یک دستور اتمیک انجام می‌دهد.
- در اولین انتقال، فقط وقتی پایگاه داده خالی است داده قدیمی را وارد می‌کند.
- پس از انتقال، داده را دوباره می‌خواند و با نسخه مبدأ مقایسه می‌کند.
- در صورت نامعتبر بودن داده، به‌جای بازنویسی یا حذف، خطا می‌دهد.

## فایل فنی

- `src/native/sqlite.ts`: ساخت پایگاه داده، خواندن/نوشتن snapshot، انتقال یک‌باره از JSON قدیمی و بررسی سلامت SQLite.
- وابستگی `expo-sqlite` برای Expo SDK 51 اضافه شده است.

## محدودیت امنیتی مهم

SQLite به‌تنهایی رمزنگاری در حالت سکون فراهم نمی‌کند. این مرحله را نباید رمزنگاری دیتابیس تلقی کرد. اتصال به Android Keystore و رمزنگاری داده‌های ذخیره‌شده باید در مرحله امنیتی جداگانه انجام شود. پشتیبان رمزدار AES-256-GCM فعلی همچنان مسیر پشتیبان‌گیری مستقل است.

## مراحل لازم پیش از فعال‌سازی در برنامه

1. افزودن پیام‌های کنترل‌شده WebView ↔ React Native برای بارگیری و ذخیره snapshot.
2. در شروع برنامه، خواندن SQLite پیش از نمایش داده‌ها.
3. اگر SQLite خالی بود، خواندن کلید قدیمی `hooman-finance-prototype-v1` از localStorage و ارسال آن برای ورود یک‌باره.
4. پس از نوشتن، خواندن مجدد و تطبیق snapshot؛ نگه‌داشتن نسخه localStorage تا پایان آزمون‌های میدانی.
5. مدیریت صف ذخیره‌سازی برای جلوگیری از به‌هم‌ریختگی ترتیب چند ذخیره متوالی.
6. آزمون قطع برنامه هنگام ذخیره، داده خراب، فضای ناکافی، به‌روزرسانی نسخه و حفظ همه بخش‌ها: دارایی‌ها، معاملات، قیمت‌ها، اشخاص، بدهی‌ها، پرداخت‌ها، چک‌ها، یادآورها، تنظیمات و تاریخچه.
7. فقط پس از موفقیت این آزمون‌ها، تغییر مسیر اصلی ذخیره‌سازی و سپس بررسی رمزنگاری با کلید محافظت‌شده توسط Android Keystore.

## قانون ایمنی داده

تا زمانی که مهاجرت کامل و تأیید نشده است، `localStorage` قدیمی نباید پاک شود. هر خطای خواندن/نوشتن باید قابل مشاهده باشد و نباید به ساخت یک حساب خالی منجر شود.

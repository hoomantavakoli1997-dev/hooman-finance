# Hooman Finance

مدیریت دارایی و حساب‌های مالی شخصی (فارسی، راست‌چین، تقویم شمسی).

## وضعیت
- مرحله ۱: هسته‌ی محاسباتی تست‌شده + نمونه‌ی وب (انجام شد)
- مرحله ۲: اشخاص، طلب/بدهی، اقساط (بعدی)
- مرحله ۳: قیمت خودکار، قفل، پشتیبان، گزارش
- مرحله ۴: اپ اندروید (Expo) + SQLite + APK

## ساختار
- `src/core/`: منطق مالی بدون وابستگی به رابط (Decimal دقیق BigInt، موتور معاملات، تقویم شمسی) و تست‌ها
- `web/`: نمونه‌ی وب (`app.ts`، `template.html`) و `build.mjs` که یک فایل `web/dist/index.html` می‌سازد
- `docs/ARCHITECTURE.md`: معماری، دیتابیس، فرمول‌ها، ابهام‌ها

## اجرا
```
npm install
npm test            # تست‌های هسته (68 tests)
npm run web:build   # ساخت web/dist/index.html
```

## قواعد مالی
- مبالغ به ریال و با کسر دقیق نگه‌داری می‌شوند؛ تومان فقط نمایش است.
- موجودی و سود هیچ‌جا ذخیره نمی‌شوند؛ همیشه از دفتر تراکنش‌ها بازمحاسبه می‌شوند.
- میانگین موزون؛ فروش میانگین را تغییر نمی‌دهد؛ کارمزد خرید در بهای تمام‌شده و کارمزد فروش از دریافتی کم می‌شود.
- فروش بیش از موجودی (در هر تاریخ) و هر ویرایش/حذفی که این را بشکند رد می‌شود.
- بدون قیمت روز، هیچ ارزشی حدس زده نمی‌شود.

## قیمت خودکار
- `src/core/prices.ts`: رابط چندمنبعی، تجزیه‌ی TGJU (`https://call.tgju.org/ajax.json`)، رد قیمت قدیمی/صفر/جهشی
- نگاشت بررسی‌شده با داده‌ی واقعی: طلا ۱۸ = `geram18`، دلار = `price_dollar_rl`، تتر = `crypto-tether-irr` (همه ریال)
- هشدار: کلید `usdt-irr` در همان پاسخ مال سال ۲۰۲۰ است و نباید استفاده شود
- نمونه‌ی پاسخ واقعی برای تست: `src/core/fixtures/tgju-ajax.sample.json`
- منبع TGJU رسمی نیست؛ منبع دوم (مثلاً بیت‌پین) هنوز بررسی نشده است

## نمای بازار
- `src/core/market.ts`: تجزیه‌ی همه‌ی قیمت‌های پاسخ TGJU، نام فارسی، دسته، واحد، کهنگی و جست‌وجو
- واحد فقط برای مواردی که مطمئن‌ایم نوشته می‌شود (ریال/دلار)؛ بقیه بدون واحد و با کلید اصلی
- نمونه‌ی ذخیره‌شده‌ی داخل نمونه‌ی وب با `npm run web:build` از فایل تست ساخته می‌شود (`web/market-sample.json`)
